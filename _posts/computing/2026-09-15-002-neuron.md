*Or: there are considerably easier ways to experiment with artificial intelligence*

There are many considerably easier ways to experiment with artificial neural networks than implementing one in Microsoft BASIC on a Z80.

So, naturally, I implemented one in Microsoft BASIC on a Z80.

It is, in practical terms, gloriously pointless. It has one numeric input, one weight, one bias and one activation function. It cannot learn. It cannot recognise handwriting, generate prose, identify cats or threaten anybody's employment.

Given a number, it multiplies it by another number, adds another number and decides whether the result is greater than zero.

And I've been having enormous fun with it.

Because the point wasn't really to build a useful artificial neuron. The point was to understand one.

## Starting Small

Modern discussions of artificial intelligence tend to begin at the wrong end of the scale. Large language models. Image generators. Self-driving cars. Neural networks containing millions or billions of parameters.

All of which are interesting, but they are also rather difficult places from which to ask the simplest question:

> **What is an artificial neuron actually doing?**

So I decided to go in the opposite direction. Not a neural network. Not even several neurons.

One.

A single input:

```text
x
```

A single weight:

```text
w
```

A bias:

```text
b
```

And an activation function.

The calculation is wonderfully small:

```text
z = wx + b
```

followed by:

```text
y = f(z)
```

That is the whole forward pass. There are considerably more sophisticated ways of writing that calculation. But on an RC2014, in Microsoft BASIC, there is almost nowhere for it to hide.

## Making the Calculation Visible

For the initial experiment I chose:

```text
w = 2
b = -6
```

which means:

```text
z = 2x - 6
```

The activation function, _f(z)_, is a simple step:

```text
if z > 0 then y = 1
otherwise y = 0
```

So the neuron switches on when:

```text
2x - 6 > 0
```

or:

```text
x > 3
```

That gives a nicely visible threshold:

```text
x = 2   ->   y = 0
x = 3   ->   y = 0
x = 4   ->   y = 1
```

Nothing remarkable is happening mathematically but that is rather the point because it makes the whole thing transparent. I can see every stage:

{% include fullwidth-image.html assets=page.assets img=page.forward_pass %}

There is no library call called something reassuringly vague like:

```text
model.predict(...)
```

There is simply multiplication, addition and a comparison. And because there is so little machinery involved, the relationship between the mathematics and the program becomes almost embarrassingly obvious.

## A Neuron in BASIC

The actual calculation is tiny:

```basic
1000 REM Forward pass: X in, weighted input V, sum Z, output Y
1010 LET V = W * X
1020 LET Z = V + B
1030 LET Y = 0
1040 IF Z > 0 THEN LET Y = 1
1050 RETURN
```

That is my artificial neuron - five executable lines of Microsoft BASIC. There is something immensely satisfying about that. Not because those five lines are clever - they aren't.

But because each one corresponds directly to something I was trying to understand.

```text
V = W * X
```

is the weighted input.

```text
Z = V + B
```

adds the bias.

And:

```text
IF Z > 0 THEN LET Y = 1
```

is the activation function. There is virtually no distance between the conceptual diagram and the running program. Which, once again, seems to be becoming a theme with the RC2014.

## The Bias Suddenly Makes Sense

The most useful part of the exercise was probably the bias. I already understood, in principle, that a neuron has weights and biases. But there is a difference between knowing that and physically changing the value in a tiny program and watching what happens.

With:

```text
w = 2
b = -6
```

the switching point is:

```text
x > 3
```

Change the bias to:

```text
b = -4
```

and now:

```text
2x - 4 > 0
```

so the threshold moves to:

```text
x > 2
```

Nothing else has changed.

- The weight is still the same
- The activation function is still the same
- The bias has simply moved the point at which the neuron switches on

That is a much more satisfying way of understanding the phrase:

> **The bias shifts the activation threshold**

than merely reading it in a textbook.

## Then I Added LEDs

At this point, of course, the sensible thing would have been to stop.

- I had the calculation
- I understood the forward pass
- The exercise had achieved its purpose

So naturally I connected it to the RC2014 Digital I/O card.

The neuron's output is binary:

```text
0
```

or:

```text
1
```

which makes it almost offensively suitable for an LED.

So now:

```text
y = 0
```

means:

```text
00000000
```

and all the LEDs remain off.

While:

```text
y = 1
```

means:

```text
00000001
```

and LED 0 illuminates and the abstract activation function has become a tiny physical event.

Enter:

```text
4
```

and somewhere inside the Z80:

```text
2 * 4 - 6 = 2
```

which is greater than zero, so the neuron fires and an LED comes on. I am entirely aware that this is a ludicrously elaborate way of switching on an LED but I was ridiculously pleased by it.

## And Then an LCD

Having established that an LED could tell me whether my artificial neuron had fired, there was obviously only one responsible course of action.

Add an LCD.

So the third version uses both the Digital I/O card and the RC2014 LCD module. For an input of `4`, the display shows:

```text
NEURON OUTPUT: 1
BINARY: 00000001
```

while the corresponding LED illuminates.

Again, none of this is necessary since the serial terminal had already told me the answer, but that is not why I added it. There is something rather pleasing about turning a tiny piece of abstract mathematics into something visible on actual hardware.

```text
input → weight → bias → activation → Z80 output → LED → LCD
```

A concept that normally exists inside software has escaped onto the front panel.

## It Doesn't Learn

There is an important limitation:

> This neuron does not learn

Its weight and bias are fixed:

```text
w = 2
b = -6
```

If I want different values, I edit the BASIC program and run it again and that is parameter adjustment, it is not training.

- There is no loss function
- There are no gradients
- There is no backpropagation
- There is nothing examining examples and modifying the weight and bias to improve the output

And I deliberately stopped there ... for now.

Because before learning how a neuron learns, I wanted to make sure I understood what the neuron is actually *doing* when it receives an input.

That seems like a sufficiently useful distinction to preserve.

## Learning Rather Than Learning

Which produces a slightly pleasing paradox:

> The neuron isn't learning, but I am

That is really what this little program is for.

- I can change the weight
- I can change the bias
- I can give it a negative weight and watch increasing inputs eventually switch the neuron *off* rather than on
- I can set the weight to zero and demonstrate that the input then has no influence whatsoever
- I can even remove the step activation and return the raw pre-activation value instead

Each experiment changes one small part of the mechanism while leaving the rest exposed.

This is not an efficient way to build artificial intelligence but it is a very good way to dismantle one small idea until I understand it.

And, to be fair, that is the purpose of the wider _Neural Network_ project on my laptop, too. I have no particular ambition to build an AI system. What I want is an insight into how these things work.

The RC2014 version simply takes that intention to an extreme: remove almost all abstraction, keep one neuron, expose every value, and watch the calculation happen.

## The Opposite End of AI

There is something rather amusing about doing this now. Artificial intelligence currently tends to be associated with enormous computers.

- GPUs
- Data centres
- Vast training datasets
- Billions of parameters

And here I am sitting in front of a Z80 computer, typing:

```basic
LET Z = W * X + B
```

That obviously doesn't make the RC2014 an AI computer in any meaningful modern sense, but it does provide an oddly useful perspective.

However complicated modern neural networks become, some of their underlying ideas remain very small.

- A weighted input
- A bias
- An activation function
- An output

You can make those ideas enormous.

But you can also make them small enough to fit comfortably inside Microsoft BASIC.

## Visibility Again

My previous experiment with machine code ended up being largely about visibility.

- Assembly became bytes
- Bytes became decimal numbers
- BASIC placed them into RAM
- The processor executed them

At every stage I could see what was happening and this experiment has ended up in much the same place.

The neuron is useful precisely because it is too small to hide its workings. I can account for every value:

```text
x
wx
b
z
y
```

- I can see the calculation on the terminal
- I can see the output on the LEDs
- I can see it again on the LCD
- And I can change one parameter and immediately understand why the behaviour changes

Once again, the attraction of the RC2014 isn't that it is a particularly capable computer.

It is that it is a **comprehensible** one.

## What Can I Make Out of It?

I keep returning to the same question with this machine.

Not:

> **What can it do?**

but:

> **What can I make out of it?**

Over the last few weeks the answer has included games, electronics experiments, aviation calculations, music and machine-code exercises.

Apparently it now includes artificial neurons.

There is something wonderfully liberating about that.

The RC2014 isn't really imposing a category on the project.

It is simply a processor, some memory, BASIC and whatever hardware I choose to connect to it.

The limits are partly technical.

But they are also imaginative.

And sometimes the most interesting projects are the ones that begin with:

> This is probably completely pointless...

followed shortly afterwards by:

> ...but I wonder if I can make it work?

So I now have a Z80 computer running a single artificial neuron.

- It will not revolutionise artificial intelligence
- It will not replace anyone's job
- It will not recognise a photograph
- It does not even know how to adjust its own weight

But I now understand rather better what that weight, bias and activation function are actually doing. And I understand them because I built the smallest version I could and watched every part of it work.

There are unquestionably easier ways to learn about artificial neurons.

But very few of them end with a Z80 lighting an LED.

And that, I think, was rather the point.
