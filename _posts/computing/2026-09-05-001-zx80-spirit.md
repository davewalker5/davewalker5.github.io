*Or: why making a Z80 light LEDs, display messages and eventually make noises turns out to interest me more than running an operating system*

About two years ago I built a CP/M card for my RC2014.

It seemed like an obvious thing to do.

CP/M is an important part of microcomputer history, the RC2014 is perfectly capable of running it and having a disk operating system opens the door to a large body of period software.

So I built the card.

And recently I came very close to abandoning it.

## The problem wasn't really CP/M

There is nothing particularly wrong with CP/M. It does what it was designed to do and, historically, it is enormously interesting.

The problem was that I wasn't enjoying using it very much.

A recent attempt to get Microsoft BASIC running neatly on the machine rather crystallised that feeling.

- I could transfer the program correctly
- I could verify that the transferred file was identical to the original

And yet I still found myself dealing with disk images, software versions, compatibility questions and the general friction associated with persuading an old operating environment to do what I wanted.

None of those problems is insoluble but that wasn't really the point.

I suddenly found myself asking a much more useful question:

> **Even if I get all of this working perfectly, is this actually what I want to do with the RC2014?**

The answer, I realised, was probably no.

## Meanwhile, something else had been happening

{% include fullwidth-image.html assets=page.assets img=page.rc2014 %}

While occasionally wrestling with CP/M, the rest of my RC2014 project had been developing in a rather different direction.

I had added a Digital I/O card - that gave me buttons and LEDs.

Then I added an LCD display - that gave programs a small physical display of their own.

The LCD eventually acquired an animated octopus called Charles, because apparently that is the sort of thing that happens around here.

And a sound card is currently on its way.

Looking at those additions together made something rather obvious.

They are the parts of the machine that I enjoy most.

## What can I make this Z80 do?

There are two subtly different questions I can ask about a retro-computer. The first is:

> **What existing software can I persuade this machine to run?**

CP/M is very good at answering that question.

But there is another:

> **What can I make this machine do?**

That is the question which increasingly seems to drive my RC2014 project.

- Can I make it calculate a great-circle distance?
- Can I connect some LEDs and manipulate them directly?
- Can I read physical buttons?
- Can I display text on an LCD?
- Can I define my own characters?
- Can I animate one of them?
- Can I turn that tiny animation into an interactive octopus with moods?

And, shortly:

> Can I make the thing produce sound?

The second set of questions is considerably more fun.

## Back to assembly

That realisation coincided with another small experiment. I started writing some simple Z80 assembly programs using Small Computer Monitor.

They are extremely modest.

- One prints a message to the serial console
- One sends a message to the LCD
- One writes a pattern to the LEDs
- One reads the buttons and displays their state

There is nothing sophisticated about any of them but that is precisely why I like them.

The workflow is essentially:

> **`A 8000` → send program → Escape → `G 8000`**

The assembler writes the machine code directly into RAM.

The program is sitting at an address I chose.

If it needs some text, I can put that text at another known address.

Then I jump to the program and watch the machine do something.

There are very few layers involved.

## Hello, Z80!

The message shown in the photograph, above, is particularly pleasing to me.

`Hello, Z80!`

It isn't being displayed by a desktop operating system.

There is no graphical environment.

There isn't even really an application environment.

A tiny Z80 program running from RAM is talking directly to a character LCD hanging off the expansion bus.

Likewise, the LEDs glowing behind it are not abstractions in a user interface.

They are physical LEDs attached to an I/O port.

Send a value to that port and the pattern changes.

Read another port and you can see which buttons are being pressed.

That direct relationship between program and physical behaviour feels important.

## The ZX80 spirit

This is where I found myself thinking about my first experiences of computing.

The ZX80 was extraordinarily limited by modern standards but that limitation was part of its character.

- You had a processor
- You had some memory
- You had BASIC
- You had a keyboard and a television

And the relationship between what you typed and what the computer did felt remarkably immediate.

I don't mean that the RC2014 is literally recreating the ZX80.

It isn't.

The hardware is different, the monitor is different and the expansion possibilities are much greater.

What it seems to recreate for me is something of the **spirit** of that machine.

A computer as a comprehensible object.

- Something you can poke at
- Something where software and hardware do not feel like entirely separate worlds

Something where the interesting question isn't necessarily which applications it can run:

> It is what you can make out of it

## Less can be more

There is a tendency in computing to regard additional capability as automatically better.

- More memory
- More storage
- More software
- More abstraction
- More features

Usually that is entirely sensible.

But it doesn't follow that every layer makes every computer more interesting.

CP/M makes the RC2014 a more capable general-purpose computer but, for me, it also puts another layer between the Z80 and the thing I am interested in exploring.

Small Computer Monitor, by contrast, barely gets in the way.

BASIC is similarly transparent.

Assembly gets closer still.

And the expansion cards turn the results into something physical.

- Press a button
- An input port changes
- Execute an `IN` instruction
- Make a decision
- Execute an `OUT`
- An LED illuminates

That sequence is wonderfully easy to understand.

## Building the wrong thing can still teach you something

None of this means that building the CP/M card was a mistake.

Quite the opposite.

- I built it
- I used it
- I learned something about CP/M

And eventually I learned something about my own reasons for building the RC2014.

That may be the more useful result.

The card can remain in the collection.

I may return to it occasionally.

There will almost certainly be moments when running a piece of historical CP/M software is interesting in its own right.

But I no longer feel that CP/M needs to sit at the centre of the project.

For me, it probably doesn't belong there.

## A small experimental computer

What I seem to be building instead is a rather different sort of machine.

At the centre is a Z80.

Around it are simple things the processor can interact with:

- Serial input and output
- Physical buttons
- LEDs
- A character LCD
- And, shortly, sound

That starts to feel less like a small desktop computer and more like a little experimental computer.

- Give it some input
- Write a program
- Make something happen
- Observe the result
- Change it
- Try again

That is an extraordinarily satisfying way to use a computer.

## What comes next

The next expansion card has already been dispatched.

It is a sound card.

I don't yet know exactly what I will do with it.

That is rather the point.

There will presumably be tones.

There will almost certainly be tunes.

There may be sound effects.

Buttons will inevitably become involved.

And given the trajectory of this project so far, it would be unwise to rule out Charles eventually acquiring the ability to make noises.

But I am no longer particularly interested in asking whether any of that makes the RC2014 more capable.

I'm interested in whether it gives me another thing to experiment with.

- Another piece of hardware to understand
- Another excuse to write some Z80 code
- Another opportunity to ask:

> **What can I make this thing do?**

That, I think, is the bit of the ZX80 spirit I had been looking for.
